## 2. 本轮具体做了什么

### 轨迹记录

1. 将暂停时间从累计用时中剔除，新增累计下降。
2. 每次接收有效轨迹点以及录制期间定时保存本机草稿。
3. 重新打开页面时恢复为“暂停”，由用户主动点击继续才启动定位。
4. 页面进入后台时暂停，避免继续显示未经实现和设备验收的锁屏记录承诺。
5. 暂停/恢复产生新的轨迹段；GPX 导出保留分段，地图不把中断点直接连起来。
6. 拒绝跨中断段沿线导航，避免把未走过的连接线当成路径。
7. 存储失败时保留当前数据并暂停；清理定位等待期间退出、重复开始等状态。

### GPX 与地图

1. 增加本机 GPX 导入：H5 文件选择、小程序聊天文件选择，以及通用粘贴入口。
2. 限制 5 MB / 20000 个点，校验 XML、坐标、海拔及时间顺序，拒绝实体声明。
3. 支持 track / route 点和多段轨迹；缺少时间的原文件不导出虚构的实测时间。
4. H5 下载释放临时 URL；小程序写入文件并调用文件分享；App 写入 GPX 文件并尝试用系统应用打开，无可用应用时提供复制内容的回退。
5. 实录轨迹保持 WGS84 存储和距离计算；地图渲染做 GCJ-02 转换。境外和边界地区、不同地图供应商仍需实机核对。
6. 内置“认知示意”、未核验和关闭路线禁止沿线导航，包括直接访问导航页面的入口。

### 云端轨迹

1. 同一账号同一轨迹使用稳定文档 ID，重复上传覆盖更新，不继续追加重复记录。
2. 服务端校验轨迹数量、坐标和时间，保存下降和有效用时。
3. 新增云端轨迹分页列表、恢复到本机、删除云端副本。
4. 删除云端副本不删除本机；本机已存在同 ID 时，恢复前让用户确认覆盖。
5. 云函数从微信可信上下文获取身份，不接受用户传入 openid 来决定归属。

### 组队和社区

1. 退出队伍真正删除服务端成员记录。
2. 停止共享清理服务端最后位置；上报与停止清理按顺序提交，减少请求交错。
3. 超过一分钟未更新的位置不再作为有效会合目标；初始 0/0 位置不会参与导航。
4. 非成员上报返回错误，不再显示成功。
5. 社区移除剩余的假用户 ID；加载失败与“没有帖子”分开显示。
6. 接通长按举报，新增 `community_reports` 集合，重复举报按用户/帖子更新。
7. 报名改为版本条件更新并有限重试，减少并发超员和覆盖。
8. 服务端校验标题、正文、出发日期和人数。
9. 队伍创建使用事务与邀请码唯一文档键；入队使用稳定成员 ID 和事务人数上限，退出同步减少计数。
10. 求助可主动发送到当前队伍，队友打开组队页面时轮询可见，发起人可解除；不是短信、系统推送或救援接警。

1. 修复桌面 GitHub Actions 中 `uses` 步骤非法设置 `working-directory` 的问题。
2. 设置 Tauri 项目目录、目标架构、平台包格式和发布权限；自动生成草稿 Release。

## 5. 确实需要你提供或完成的事项

### A. DCloud 账号与 AppID（已完成，以下保留办理步骤）

1. 在 DCloud 开发者中心登录你自己持有的账号：<https://dev.dcloud.net.cn/>。
2. 在应用管理中创建/选择“徒步地球”的 uni-app 应用，取得 DCloud AppID（通常以 `__UNI__` 开头）。这不是微信的 `wx...` AppID。
3. 将 AppID 告诉 Codex，或者自己填到 `app/src/manifest.json` 最外层 `appid`。无需发送账号密码。
4. 在本机 HBuilderX 中完成账号登录。当前机器此前未发现 HBuilderX；官网下载页的命令行下载返回 403，自动下载安装尚未完成。官方下载：<https://www.dcloud.io/hbuilderx.html>。
5. 后续导入项目、填回配置、重新编译、选择 Android 包名、生成证书和构建 APK 由开发端接着完成。若平台要求实名认证/验证码，由你在官方界面完成。

正式发布所用 Android 证书需要长期保管，后续升级须保持签名一致；证书和密码不放 GitHub。

### B. 微信开放平台 / CloudBase 登录配置

1. 登录你拥有管理权的微信开放平台和 CloudBase 控制台。
2. 原生微信登录需要对应“移动应用”的资料和 AppID；现有小程序 AppID 不能直接充当原生移动应用 AppID。
3. 在官方控制台完成主体认证、应用登记等账号所有者操作。
4. 把非敏感 AppID、已登记包名和 Bundle ID 告诉 Codex。AppSecret 等凭据直接设置到服务器环境，不发在聊天或公开仓库。
5. 有这些身份配置后，由开发端完成客户端 SDK、服务端校验和实际联调。单纯填 AppID 不能保证现有 App 云功能立即可用。

### C. 地图服务

需要你持有的地图开发者账号和应用登记。确定地图供应商及 SDK 使用范围后，由开发端生成证书摘要、配置 Android/iOS 标识和接入地图。离线地图是否可用取决于供应商许可及技术能力；不能抓取无授权瓦片冒充离线地图包。

### D. iPhone 的安装路线

未签名 IPA 不能通过勾选隐私设置安装到普通 iPhone。你需要在自己的 Apple 账号下选择实际分发方式：开发设备安装、TestFlight 或 App Store；签名授权、协议和必要的账号认证由你完成。之后原生构建和分发配置由开发端完成。

如果先采用 Safari“添加到主屏幕”，那是网页方式，后台定位和原生能力范围不同；不能将它说成 iOS 原生安装包。

### E. 上线资料与设备

正式上线前需要真实运营主体、隐私联系邮箱、举报处理责任人、获准使用的路线/地图/商品链接，以及至少一台可安装调试的 Android 手机。Apple 账号授权、设备上的系统权限确认及你本人持有的验证码不能由开发端代替。

## 6. Android 后续安装过程（拿到 APK 后）

1. 在手机浏览器打开实际发布的下载链接，下载 `.apk`。
2. 如果 Android 提示，为这次用于安装的浏览器/文件管理器开启“允许安装未知来源应用”。不同厂商菜单名称可能不同。
3. 安装后在应用“我的 → 隐私设置”按需要打开定位、组队共享、轨迹备份和照片分析。
4. 首次记录时允许系统定位权限；结束或撤回后停止对应处理。
5. 对是否需要关闭“未知来源安装”由用户按设备使用习惯决定。它和应用内隐私开关是两件不同的设置。

APK 已在 `app/dist/delivery/hiking-earth-0.1.0-android.apk` 和本机下载文件夹中提供，尚未公开发布网页下载地址。
