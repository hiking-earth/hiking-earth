# 路线发现与更新

独立 ODbL 数据集：`shared/data/catalog/osm.json`，保留 © OpenStreetMap contributors 和 https://www.openstreetmap.org/copyright。人工维护数据与 OSM 快照分开保存。OSM 标识去重，显示层标准化名称加近似位置去重；不同来源同名可能合并，后续统一测试检查。

`python3 scripts/update-route-catalog.py` 每次检查中国、欧洲、北美、日本、大洋洲、南美、非洲、南亚八个区域内带名称的徒步关系近期变更。首次建立区域水位时从源快照生成时间前24小时回看（参数可设1至168小时），后续使用OSM复制水位并回退10分钟留重叠；失败区域不推进水位，等下一轮再试。公共源预算为每天最多64次请求、8 MiB响应数据、单响应1 MiB；不对失败请求立即重试。快照记录UTC日用量，供Actions摘要审计。更新周期是每6小时检查，不是实时推送。范围仍非全球全部徒步路线；只抓发现档案，不拼接可能断裂的关系成员作为导航轨迹。

亚洲国家补录使用独立的 Geofabrik ODbL `.osm.pbf` 区域快照：`scripts/refresh-asian-osm-pbf.py` 为47个国家/次区域来源逐一下载、校验来源校验和，再导入 `asia` 发现区域。印度采用6个分区，印度尼西亚采用7个岛区；单文件上限900MB，未涵盖完整印度、完整印度尼西亚、俄罗斯及其它大文件；导入器另按文件大小至少预留6倍临时磁盘空间，不足时安全跳过。工作流 `refresh-asian-osm-pbf.yml` 设计为每月运行，校验后重建OSM分页快照、双云函数回退副本并提交逐来源报告；分页生成器保留当前版、上一版和受保护的生产回退版，回退快照缺失时会停止；只有分页快照准备成功时才会提交，避免原始目录更新但客户端目录停留旧版本。它只有在工作流合入默认分支、GitHub Actions可用且有写入目标分支权限时才会自动执行。它不使用公共 Overpass 扫描亚洲大框，也不核定开放状态或导航授权。Geofabrik和OSM均要求按 ODbL 1.0保留署名；参考 [Geofabrik Asia](https://download.geofabrik.de/asia.html)。

**全域历史网格回核目前暂停自动执行。** OpenStreetMap Overpass官方文档明确把拼接边界框抓取完整世界资料列为不推荐用法，建议这类大范围资料改用planet/区域摘录；OSM Wiki也建议重复采集项目降低到少于100次请求及约10 MB/日并优先用区域摘录。现存全域网格检查点193/1226完成、1033待处理，保留以供迁移；公共Overpass不再定时跑这1,226格。恢复历史覆盖需要改用获准区域PBF/planet增量处理，或由所有者提供已授权、可持续并承担费用的服务。来源：[Overpass官方公共实例指南](https://dev.overpass-api.de/overpass-doc/en/preface/commons.html)、[OSM Wiki Overpass API](https://wiki.openstreetmap.org/wiki/Overpass_API)。

稳定关系 ID 更新同一路线；区域失败保留旧记录；全失败不覆盖文件；原子替换。源记录暂时消失不自动删除，避免数据源短时故障误删。每条保留采集时间、来源原值和待核验状态。采集时间不等于官方开放核验时间。

GitHub Actions 每6小时运行其它来源更新及有预算的OSM近期变更检查，workflow_dispatch 支持手动触发。并发运行由workflow group串行化。定时任务只有进入默认分支后才运行；是否实际执行须查看Actions记录。此阶段没有执行应用测试或构建。

全端客户端服务 `app/src/services/route-catalog.ts` 使用响应式目录；启动/回到前台最多每6小时获取一次 HTTPS 最新快照，保留上次缓存作为离线回退。`VITE_ROUTE_CATALOG_URL` 可以改为自有 CDN；默认 GitHub raw main。微信小程序需由账号所有者把快照服务域名加入 request 合法域名，建议生产使用自有 HTTPS 域名。后台抓取定时更新，前台刷新跟随快照；不是官方路况秒级实时服务。

第二个独立数据源为 USDA Forest Service 官方 National Forest System Trails 图层。`scripts/update-usfs-catalog.py` 每轮最多分页获取5000个有名称的源路段（最新页刷新加历史objectid游标），按 trail_cn 合并为路线发现档案，保存源单位和徒步用途属性及季节性徒步限制字段；受限记录仍仅是待核验发现，不代表获准通行。不把源路段长度冒充完整路线长度；森林服务各单位提供的属性完整度不同。不与 ODbL 快照混用许可。任何分页失败三次则保留前一次完整快照。

客户端和网页列表采用50条递增加载。网页地图按视野最多显示400个路线标记，完整档案仍可搜索；尚未性能验收。

OSM近期变更按地区独立提交水位；单区失败保留该区旧水位和记录，其余成功地区可继续保存。第一次从现有快照生成时间前24小时回看并使用源复制水位，服务端暂时落后时不推进游标越过水位。更新时保留目录内的成员回核状态和已有状态字段。USDA按objectid倒序获取最新源路段并合并历史快照。增量缺席不自动删除记录；OSM完整成员回核现暂停，USDA历史回填状态依旧单独呈现；路线撤下/官方禁行仍需独立审核。

## 续跑开发补充

- 两个采集步骤分别设置失败继续；单源失败不阻止另一个源采集和成功快照发布。两个源都失败时任务最终标记失败，避免无变化被误报为刷新成功。
- Actions 摘要分别列出采集结果；整项取消时不发布。任务总预算40分钟，USDA10分钟、OSM25分钟。
- OSM增量游标依据源端复制时间戳并回退10分钟，防止本机时间领先或源更新延迟漏掉记录；缺少源水位时保留旧游标重复采集。USDA空结果不把旧目录重新标记为已刷新。
- 本轮仅写入源码和说明，没有执行采集、应用测试或构建，未将这次修正发布到默认分支。
