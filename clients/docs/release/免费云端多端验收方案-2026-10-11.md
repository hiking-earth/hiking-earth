# 免费云端多端验收方案（2026-10-11）

## 结论

优先复用公开仓库 `hiking-earth/clients` 的 GitHub Actions，不增加付费服务：公开仓库的标准 GitHub 托管 Runner 使用免费；Linux Runner 支持 Android SDK 硬件加速，macOS Runner 可用于 Xcode/iOS Simulator 工作流。它们适合最终统一检测阶段的构建、浏览器视口和模拟器自动化。该仓库当前已核实为 Public。

Android 额外可用 Firebase Test Lab Spark 免费配额，每个 Firebase 项目每天最多 10 次虚拟设备测试（另有最多 5 次实体设备测试）；配额是项目级，达到上限需等次日，不启用 Blaze 付费方案。只有在最终测试阶段确有需要时再接入，不在功能开发中途触发。

## 端与环境边界

| 端 | 可用的免费云端途径 | 能验收 | 不能替代 |
|---|---|---|---|
| 网页 / 桌面 WebView | GitHub Actions Linux 浏览器自动化 | 页面加载、布局断点、登录交互壳、滚动与基本客户端路由 | 真实 GPU、实际地球渲染帧率、桌面操作系统安装/签名 |
| Android | GitHub Actions Linux Android Emulator；可选 Firebase Test Lab Spark 虚拟设备 | 安装、启动、屏幕尺寸、基本导航和 UI 自动化 | 真机后台定位、厂商省电限制、真实传感器、推送可靠性 |
| iPhone 网页/PWA | GitHub Actions macOS 的 iOS Simulator/Safari（安装完整 Xcode 与模拟器运行时后） | Safari 页面与视口、触控布局的自动化近似检查 | 真机性能、硬件特性；模拟器不等于实体 iPhone |
| iOS 原生 App | macOS Runner 的 iOS Simulator（仅当项目有可构建的 iOS 原生目标时） | 模拟器构建、启动、基础界面检查 | App Store 分发签名和实体设备权限验收 |
| 微信小程序 | 微信开发者工具 CLI/自动化模拟器 | WXML/逻辑在工具模拟环境中的基础运行与截图 | 微信账号授权、真实手机号授权、微信线上审核与真实用户态 |
| Mac/Windows/Linux 桌面包 | GitHub Actions 对应系统 Runner | 对应平台构建、文件完整性、可运行性脚本 | 用户电脑权限弹窗、公证、实际硬件适配和升级安装体验 |

## 适用于当前项目的实施顺序

1. 先完成功能开发和源码冻结；依照既定要求，之前不启动新一轮统一功能测试或新版本发布构建。
2. 最终验收阶段，使用 GitHub Actions 在 Linux 上跑 Web 与 Android Emulator，在 macOS 上跑 iOS Simulator/Safari；工作流只上传无凭据的报告、截图和哈希。
3. Android 如需云端多机型覆盖，先用 Firebase Spark 每日免费虚拟设备配额；确认项目仍处 Spark、工作流不启用计费方案。
4. 模拟器/虚拟设备通过后，再进行用户已有 Mac、iPhone 和微信客户端的必要实机步骤。地点、定位、系统隐私授权、微信账号授权等不能由模拟器结果代替。
5. 只有所有功能和最终产物完成后才生成统一验收报告、签名/哈希和发布清单。

## 当前阻塞与证据边界

- 本机当前仅装有 Apple Command Line Tools，没有完整 Xcode，`simctl` 不可用；因此不能在本机直接运行 iOS Simulator。macOS 托管 Runner 是可选的云端替代方式，但需在最终验收阶段通过 Actions 验证对应模拟器镜像是否包含所需 Xcode/运行时。
- Apple 明确说明 Simulator 无法复制全部设备硬件能力，模拟器结果不能取代实体设备检查。
- Firebase Test Lab 的免费数额会受当前项目计划与配额规则约束；本方案按官方当前 Spark 文档记录，使用时重新核对项目计划和配额，且不升级到付费计划。
- 本文件是云端验收方案与官方配额核对记录，不是测试、构建、部署或设备验收结果。
