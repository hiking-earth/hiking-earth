## 2. 既定技术决策（2026-10-02 与用户确认）

| 决策点           | 结论                                                    | 理由                                                     |
| ------------- | ----------------------------------------------------- | ------------------------------------------------------ |
| 手机 App + 小程序  | **uni-app（Vue3）同一套代码**                                | 一套代码出 iOS/Android App、微信小程序、H5；器材通已有 uni-app 经验        |
| 电脑端（Mac/Win）  | **Tauri 套壳现有网页端**                                     | 包裹 hiking-earth 网页，最快上线；器材通已用过 Tauri                   |
| 代码组织          | **Monorepo 单仓库**（本文件夹）                                | 个人开发跨端同步成本最低                                           |
| 账号体系          | **轻量账号：微信一键登录，后置到 M2 末**                              | unionid 打通小程序 + App；M1 纯本地离线优先（户外无网是常态）；不自建密码体系，合规成本最低 |
| 客户端 GitHub 仓库 | **hiking-earth 组织下新开客户端仓库**（如 `hiking-earth/clients`） | 网页仓库保持干净，客户端独立 CI/发布，品牌归属统一                            |
| 后端方案          | **微信云开发（CloudBase）**                                    | 小程序服务器域名必须 ICP 备案，不备案前提下 Workers/FastAPI 自建都走不通；云开发免备案、登录免鉴权、内置内容安全 API、实时推送支撑组队共享；App 端走 HTTP 云函数/Web SDK |
| 商城形态          | **个人主体 + 装备导购**（跳第三方成交）                             | 个人办不了增值电信证和微信商户号；导购模式合规成本最低，无需办证                          |
| .com 域名 / 备案   | **先不做**，网页版继续用现有部署地址                              | 与微信云开发选型自洽（免备案）                                         |
| 小程序类目        | **运动户外类**                                              | 导航功能的测绘资质边界上架前再确认                                          |
| 内容审核          | **机审 API（微信内容安全）+ 举报通道**                            | 云开发内置内容安全能力，社区 UGC 先过机审                                   |

## 4. App 功能方案（借鉴两步路 + 差异化升级）

### 4.1 两步路核心模块拆解（借鉴对象）

| 两步路模块        | 是否借鉴          | 我们的做法                                            |
| ------------ | ------------- | ------------------------------------------------ |
| 轨迹记录         | ✅ 借鉴          | GPS 轨迹记录：里程/时长/海拔/配速，暂停继续、后台保活、省电策略              |
| 路网/路线库       | ✅ 借鉴          | 路线库搜索筛选 + 轨迹数据来自网页端上游（不自建爬虫路网）                   |
| 沿轨迹导航        | ✅ 借鉴并**重点升级** | 独立导航模块，见第 5 节专项                                  |
| 离线地图         | ✅ 借鉴          | 离线地图包下载管理（户外无网刚需）                                |
| 组队位置共享 / SOS | ✅ 做（M4）       | 队友实时位置共享、一键 SOS（紧急联系人 + 位置上报）；涉他人位置=敏感个人信息，需明示授权；**M4 升级为「组队会合」：成员列表实时双向距离 + 点队友进入箭头导航会合（类苹果查找，目标为动态位置）** |
| 约伴社区         | ✅ 做（M4）       | 约伴发帖、活动报名、路线动态；UGC 必须配内容审核（先机审 API + 举报通道）       |
| 户外商城         | ✅ 做（M5）       | 装备导购：个人主体，跳转第三方成交（淘宝/京东联盟、微信小商店带货），不自营不收款，无需办证 |

### 4.2 差异化升级点（与两步路的区别）

1. **主页对标网页版**：网页版 hiking-earth 的 3D 地球路线发现体验移植到 App——全球视野 + 季相探索 + 路线卡片，而非两步路式的国内路网首页。M1 先用 2.5D 地图 + 路线卡片起步，3D 地球（uni-app 内 renderjs + three.js）作为技术验证增强项。
2. **导航模块精做**：在两步路沿轨迹导航基础上，升级为类苹果"查找"的精准箭头指向体验（见第 5 节）。
3. **组队会合**（M4）：类微信位置共享的队友互见 + 双向实时距离，点队友直接进入箭头导航会合——箭头指向的是**动态目标**（队友实时位置），两人移动时指向与距离实时更新。
4. **拍照识装备**（M4）：拍装备照片 → 云端视觉大模型识别 → 输出已识别清单 / 缺少项（按路线给优先级与原因）/ 使用要点 / 完整打包清单（可勾选）。模型走 OpenAI 兼容视觉接口（key 存云函数环境变量，不入库）。

### 4.3 App / 小程序页面结构

```
底部 Tab（5 个）：
├── 首页（发现）   ← 对标网页版：路线发现 / 搜索筛选 / 路线卡片（M1 2.5D → 增强 3D 地球）
├── 约伴           ← 社区（M4）：约伴帖 / 活动报名 / 路线动态
├── 导航           ← 独立模块入口，进入后全屏沉浸式（见第 5 节）
├── 轨迹           ← 记录（开始/暂停/结束、实时数据面板）+ 我的轨迹管理 + GPX 导入导出
└── 我的           ← 微信登录（M2 末接入）、轨迹云同步、离线地图包、装备导购入口（M5）、设置
```

## 5. 导航模块专项（单独做，核心差异化）

### 5.1 定位

独立目录 / 独立页面栈的全屏沉浸式模块：导航中屏幕常亮、后台保活、震动 + 语音播报。这是 App 的杀手级功能，投入优先级最高。

### 5.2 基础能力（借鉴两步路）

- 沿轨迹导航：选定轨迹后沿线路径引导
- 偏航提醒：偏离轨迹超过阈值 → 震动 + 语音告警
- 关键点播报：标注点（水源/营地/岔路口）到达前播报
- 原路返回：一键反向导航

### 5.3 核心升级：类苹果"查找"的精准箭头指向

> 技术说明：苹果精准查找的箭头靠 UWB 超宽带（厘米级、几十米内）。户外是公里级场景，方案是 **GPS + 电子罗盘实现"视觉同构"的箭头指向体验**（米级精度）——界面上与苹果查找一致：一个大箭头实时指向目标，配上实时距离。

**界面形态**：

- 中央大箭头：实时指向下一路径点方位，随手机朝向平滑转动
- 大字号距离 + 方位角 + 预计到达时间
- 到达阈值（如 15m）自动切换下一路径点，全程无需看地图
- 可切"箭头模式 / 地图模式"

**技术链路**：

```
GPS 位置（腾讯/高德定位 SDK）
   + 设备航向（iOS CoreLocation CLHeading / Android 旋转矢量传感器：地磁+陀螺仪融合）
   → 计算当前位置→目标点方位角 bearing
   → 箭头角度 = bearing − 设备 heading
   → 低通/卡尔曼滤波防抖 → 渲染
```

- ⚠️ 技术风险项：uni-app 标准 API 拿不到高精度融合航向，需要 **uts 原生插件**（或评估三方插件），M1 必须先做这个验证，验证不过则导航降级为地图模式为主。

**远期增强**：AR 实景箭头（摄像头画面叠加方向指示）、手表联动。

## 6. 关键架构约束

1. **上游基线先行**：动工第一步 `git clone hiking-earth/hiking-earth`，从源码提取数据模型（路线/轨迹/季相/天气字段）写入 `shared/types/`，禁止凭产品描述自编模型。
2. **地图双轨制（合规硬约束）**：
   - 网页端 / 桌面端（Tauri）→ MapLibre（3D 地球）
   - App / 小程序 → **腾讯地图**（默认合规源；uni-app map 组件 / 小程序原生组件），GCJ-02 坐标系
   - 禁止：Google Maps、Apple Maps、Mapbox、OSM 境外瓦片等一切无资质图源
3. **定位数据合规（个保法）**：轨迹属敏感个人信息——本地优先存储；云同步/位置共享需明示授权；不得收集发布他人位置。
4. **后端已定：微信云开发**：网页端没有独立后端；客户端侧账号、云同步、组队共享、社区、导购数据统一走微信云开发（免备案）。App 端通过 HTTP 云函数 / Web SDK 访问同一套后端。
5. **品牌一致性**：图标、名称、URL 以网页端仓库实际资产为准，统一放 `assets/` 与 `shared/constants/`。
